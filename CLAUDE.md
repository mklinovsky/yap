# yap

Push-to-talk dictation for macOS (Windows/Linux possible later), in the spirit of superwhisper / Whispering but deliberately small: press a global shortcut, speak, the audio goes to an OpenAI-compatible transcription endpoint, the text is pasted at the cursor and saved to history. Optional transformations (named LLM prompts via an OpenAI-compatible `/chat/completions` endpoint) can rewrite the transcript before pasting. Personal tool, shared as-is.

## Stack

- Tauri 2, Rust backend (`src-tauri/`), React 19 + TypeScript + Vite frontend (`src/`), pnpm.
- Rust crates: `cpal` (mic + sound cues), `rubato` (FFT resampler), `flacenc` (pure-Rust FLAC, default features off), `reqwest` blocking + multipart + rustls (HTTP), `rusqlite` bundled (storage), `enigo` (Cmd/Ctrl+V), `arboard` (clipboard), `tauri-plugin-global-shortcut`, `tauri-plugin-autostart` (open at login), `thiserror`. Dev: `mockito`, `claxon` (FLAC decoding in tests).
- Frontend tests: Vitest + jsdom + Testing Library + user-event, Tauri IPC faked with `mockIPC` from `@tauri-apps/api/mocks`.

The bundle is ad-hoc signed (`bundle.macOS.signingIdentity: "-"`), not notarized, so downloaded copies need `xattr -dr com.apple.quarantine` or Open Anyway (README Install step). ## Architecture

```
global shortcuts ─► mpsc worker thread ──► Dictation (state machine)
Try it button ──► toggle_recording ─┤          │
tray pick / Use once ───────────────┘          │
                                               ├─ Recorder (cpal)         start/stop → Recording
                                               ├─ encode_flac             16 kHz mono 16-bit FLAC
                                               ├─ Transcriber (reqwest)   POST {base}/audio/transcriptions
                                               ├─ Transformer (reqwest)   POST {base}/chat/completions
                                               ├─ Store (SQLite)          settings, history, API key
                                               ├─ Paster (arboard+enigo)  clipboard + Cmd/Ctrl+V
                                               └─ Feedback (tray)         icon, status text, sounds, events
```

Backend (`src-tauri/src/`):
- `dictation.rs` — the core. `Dictation` holds `Deps` (all boundaries as `Arc<dyn Trait>`: `Recorder`, `Transcriber`, `Transformer`, `Paster`, `Feedback`, `Secrets`, `Spawner`, `Timer`, `Clock`, plus `Arc<Store>`). `handle(ShortcutEvent)` for hold/toggle modes (`Pressed(Apply)` with `Apply::TrayPick` for the dictation shortcut, `Apply::Transformation(id)` for a transformation's own shortcut; `Released`), `toggle()` for the button (mode-independent, `TrayPick`), `status()`, tray state via `select(Option<id>)`, `set_use_once(bool)`, `tray_state()`, `clear_pick_if_deleted()`. Status: `Idle | Recording | Transcribing | Transforming | Error(String)`, serialized as `{"state": "...", "message"?: "..."}`.
  - No API key → `Error("API key is not set. Open Settings to add it.")` on press, nothing recorded.
  - Recording < 0.3 s or peak < 0.01 → discarded, back to Idle, no API call.
  - Transcript is trimmed; blank → Idle, nothing pasted, no history.
  - History is saved before pasting, so a paste failure (`Error`) still keeps the text. The transcription cost, recording duration (s), uploaded FLAC size (bytes), and how long encoding and the transcription request took (s, measured with `Clock`) are stored with the entry; blank transcripts are billed but not recorded.
  - Press while Transcribing or Transforming is ignored; Error behaves like Idle on the next press.
  - Each start schedules `Timer::after(maxMinutes)`; when it fires (on the worker thread) and that same recording is still running, it finishes like a manual stop. A per-recording counter makes timers of earlier recordings no-ops. A Hold release arriving after the auto-stop is ignored.
  - Cues (`Cue::Start/Stop`) only when `settings.sounds`.
  - Transformations: only while `transformations.enabled`. The transformation is resolved when the recording stops (explicit id from its shortcut, else the tray pick), so a pick changed mid-recording counts; a recording started by a transformation shortcut keeps it even if another shortcut stops it. A missing key is reported on press when the transformation is already known (nothing recorded) and again after transcription (raw kept in history). Key: transcription key when `reuseApiKey`, else the transformation key; base URL `transformations.baseUrl` or the transcription one; model: the item's or `defaultModel`. Success: history gets `text` = transformed, `raw_text`, name, `transform_cost`/`transform_time`, then paste. Failure (HTTP/network error or blank answer → `"Transformation returned no text"`): `Error`, nothing pasted, history `text` = raw plus name and `transform_error`.
  - Tray pick with Use once: consumed only when a non-blank transcript goes to the transformer (kept on discard, blank transcript or missing key at press; consumed even if the call then fails). A transformation's own shortcut never consumes the pick. The pick is persisted (`tray_state`) only while Use once is off; every change calls `Feedback::tray`.
  - Transcription runs via `Spawner` (threads in the app, a queue in tests).
- `store.rs` — `Store` (Mutex<Connection>), tables `settings`, `transformations`, `tray_state` (one JSON row each, separate so no form overwrites another's data), `history` (`id, text, created_at, cost REAL, duration REAL, size INTEGER, encode_time REAL, transcribe_time REAL, raw_text TEXT, transformation TEXT, transform_error TEXT, transform_cost REAL, transform_time REAL`, all after `created_at` nullable; `migrate()` adds missing columns to older DBs). `HistoryEntry`/`NewHistoryEntry` name the units instead (`cost_in_usd`, `duration_in_seconds`, `size_in_bytes`, `encode_time_in_seconds`, `transcribe_time_in_seconds`, `transformation_name`, `transform_cost_in_usd`, `transform_time_in_seconds`; camelCase in JSON). `add_history(&NewHistoryEntry)`, `secrets` (`api_key`, `transform_api_key`). `Transformations { enabled, baseUrl: Option (None until first saved), reuseApiKey (default true), defaultModel ("gpt-6-luna"), items: [Transformation { id, name, systemPrompt, userTemplate, model: Option, shortcut: Option }] }`; `validate(dictation_shortcut)` (name required, non-empty template must contain `{{transcript}}`, no shortcut equal to the dictation one or shared by two items); `Transformation::user_message(transcript)` (empty template → transcript alone). `TrayState { selected, useOnce }` (default None, true). `Settings { baseUrl, model, languages, keywords, inputDevice, shortcut, mode, sounds, maxMinutes }` camelCase JSON. Defaults: `https://api.openai.com/v1`, `gpt-transcribe`, no languages (auto-detect), no keywords, system default input (`None`), `Shift+Super+Semicolon` (⌘⇧;), Hold, sounds on, max length 5 min (`#[serde(default)]`, so older rows load as 5). `upgrade()` migrates the legacy single `language` field to `languages`. `keywords` has `#[serde(default)]`. API key: `api_key()`, `set_api_key("")` deletes, `api_key_preview()` masks (`sk-p••••••••`, 2 visible chars if key ≤ 12). `Store` implements `dictation::Secrets` (in `lib.rs`).
- `http.rs` — shared by transcriber and transformer: `ApiError` (`Http { status, message }`, `InvalidResponse`, `Network`), `client()` (timeouts below), `endpoint(base, path)` (trims trailing slash), `body_and_cost_in_usd(response)` → body + LiteLLM cost or `Http` error (message from `{"error":{"message"}}` or raw body).
- `transformer.rs` — `HttpTransformer`: JSON `{model, messages: [system (omitted when the prompt is empty), user]}`, reads `choices[0].message.content` (null → empty text; no choices → `InvalidResponse`), returns `Transformed { text, cost_in_usd }`.
- `transcriber.rs` — `HttpTranscriber`. Multipart `model`, `response_format=json` (otherwise LiteLLM routes non-`gpt-4o` OpenAI models through its Whisper config, which fills in `verbose_json`; `gpt-transcribe` rejects that), `file` (`audio.flac`, `audio/flac`). Model-specific: if the model name after the last `/` starts with `gpt-transcribe` (LiteLLM names it `openai/gpt-transcribe`) → every language as `languages[]` and every keyword as `keywords[]`; otherwise only the first language as `language`, no keywords. Returns `Transcription { text, cost_in_usd: Option<f64> }`; cost (USD) comes from LiteLLM's `x-litellm-response-cost` header, `None` when absent/unparsable (e.g. OpenAI direct). Errors are `ApiError`. Client timeout is 15 min (reqwest's 30 s default would kill long recordings), connect timeout 15 s.
- `audio.rs` — `encode_flac(samples, rate, channels)`: downmix by averaging, band-limited resample to 16 kHz (`rubato::Fft`, `process_all`; the old linear interpolation aliased everything above 8 kHz into the speech band), clamp, ×32767 rounded, FLAC 16-bit. Roughly half the size of the equivalent WAV; 60 s of 48 kHz input encodes in ~30 ms (release). FLAC can't encode streams shorter than 16 samples (irrelevant past the 0.3 s gate). Chosen over native-rate upload (bigger, no proven accuracy gain) and Opus (lossy, C dependency).
- `recorder.rs` — `CpalRecorder`. `Recorder::start(device)` gets the saved cpal `DeviceId` string (stable across runs; display names can repeat); unknown/unplugged id or `None` → system default input. `input_devices()` lists `{id, name}` for the Settings picker. The cpal stream lives on its own thread (not `Send` everywhere); start waits for a ready signal so device errors surface synchronously. Handles F32/I16/I32/U16.
- `paster.rs` — `ClipboardPaster`: sets clipboard (keeps one `arboard::Clipboard` alive — X11/Wayland serve clipboard from the owner), then Cmd+V (macOS) / Ctrl+V via enigo **on the main thread** (`run_on_main_thread`; enigo's keyboard-layout lookups crash off-main on macOS). Afterwards the previous clipboard is restored: saved as text or image before pasting, put back 300 ms after Cmd+V (the target app reads the clipboard asynchronously), skipped if something else was copied meanwhile; other formats (e.g. copied files) can't be read, so the transcript stays. `copy_text` uses the same clipboard without restoring.
- `tray.rs` — `TrayFeedback`: builds the tray menu and `rebuild()`s it (`set_menu`) when transformations change: status line, then while enabled a disabled "Transformation" header, None + one check item per transformation, separator, "Use once"; then "Open yap…", "Quit yap". Check items flip their own mark on click (no native radio groups), so `refresh` re-applies all marks from the real state after every change. Status line and tooltip append the pick (`Idle · Fix grammar`). Icon is generated in code: template dot idle, red dot recording, amber dot transcribing/transforming, template warning triangle error. Red means recording only (a red error ring read as recording), tooltip + disabled status menu item, emits `status-changed` and `history-changed`. Cues are synthesized sine beeps through cpal output (880 Hz start, 660 Hz stop) — `rodio` was dropped to avoid a second audio stack.
- `lib.rs` — wiring: commands `get_settings, save_settings, get_transformations, save_transformations, transform_api_key_preview, set_transform_api_key, api_key_preview, set_api_key, list_history, delete_history, copy_text, list_input_devices, get_status, toggle_recording, pause_shortcut, resume_shortcut, get_open_at_login, set_open_at_login`; open at login = autostart plugin with the macOS LaunchAgent launcher (`~/Library/LaunchAgents`, no System Events permission prompt), state lives only in the OS, not in SQLite; one worker thread consumes `Input::{Shortcut, Toggle, Select, SetUseOnce, Run}` so press/release and tray picks stay ordered off the main thread; global shortcuts: `bindings(settings, transformations)` = dictation shortcut (`Apply::TrayPick`) + enabled transformation shortcuts, `register_all_or_none` records shortcut id → `Apply` (`apply_by_shortcut_id`) for the handler, `rebind_or_restore` restores the previous set if any is refused (used by `save_settings` when the shortcut changed, `save_transformations` when bindings changed, `resume_shortcut`, startup); both saves run `Transformations::validate`; `save_transformations` then calls `clear_pick_if_deleted()` and `rebuild()`; `WorkerTimer` sleeps on its own thread and posts `Input::Run(job)` back to the worker; tray menu = status line, "Open yap…", "Quit yap"; single window `main` (780×800, tall enough for Settings without scrolling, min 640×420, dark theme, macOS overlay title bar + hidden title + transparent + Sidebar vibrancy); `open_window` always calls `set_focus()`; macOS `RunEvent::Reopen` (launching yap again while it runs) opens the window; `pause_shortcut` also sends `Released` to the worker, since an unregistered shortcut never reports its release and a Hold recording would keep running; app is `ActivationPolicy::Accessory` (tray only, no Dock); `ExitRequested { code: None }` is prevented so closing the window doesn't quit; Settings window opens on launch when no API key. `save_settings` re-registers shortcuts only when the dictation shortcut changed.

Frontend (`src/`, one folder per sidebar section, each page test next to its page; shared pieces in `components/`):
- `api.ts` — typed `invoke` wrappers, `Settings`/`HistoryEntry`/`Status` types, event names `history-changed`, `status-changed`.
- `App.tsx` — sidebar shell, order **Settings, Transformations, History, Try it**, opens on Settings (`main.tsx`). `main.tsx` adds `html.mac` for mac-only styling (transparent body + sidebar padding for traffic lights).
- `components/` — `ShortcutRecorder` (below), `SecretInput` (API key field: always empty, placeholder = masked preview, eye button only while typing; used by Settings and Transformations), `SaveBar` + `useSaveState(dirty)` (pinned bar with "Unsaved changes" / "Saved" / backend error and the Save button; `onSubmit(save)` wraps a page's save).
- `settings/Settings.tsx` — page state and save; `TranscriptionGroup` and `DictationGroup` (which polls input devices) render the rows. Grouped rows (Transcription: Base URL, API key, Model, Languages, Vocabulary; Dictation: Input device select — "System default" first, then devices, "Disconnected device" if the saved one is missing; the list is re-read every 2 s while Settings is open — Shortcut, Mode segmented, Max length select (1, 2, 5, 10, 15, 20 min; OpenAI's 25 MB upload limit is roughly 20 min of FLAC), Sounds switch, Open at login switch — loaded from `get_open_at_login`, sent with `set_open_at_login` on Save only when changed), explicit Save button (no autosave) in a bar pinned below the scrolling groups (Settings scrolls its own `.settings-scroll`; `.content-body[data-section="settings"]` and `"transformations"` don't scroll). Save is disabled until the form differs from the last saved snapshot (incl. a typed API key); bar shows "Unsaved changes" / "Saved" / the backend error, and a failed save stays dirty so it can be retried. API key field is always empty; placeholder = masked preview; eye button only appears while typing a new key. Vocabulary is comma-separated text → trimmed `keywords` array on save.
- `transformations/Transformations.tsx` — page state, draft and save; `ConnectionGroup`, `TransformationList`, `TransformationEditor` render the parts. Same page shell as Settings (pinned Save bar, Save disabled until dirty, one draft for the whole section). Overview: Connection group (Enabled, Base URL showing the transcription URL until first saved, "Use transcription API key" switch, API key field only when it is off, Default model) and the list (rows `Edit <name>` with model or "default model", shortcut or "No shortcut", plus "Add transformation"). - `settings/LanguagePicker.tsx` — chips with remove buttons + "Add language…" select; empty = "Auto-detect". `languages.ts` pins `en` first.
- `components/ShortcutRecorder.tsx` — click → pauses global shortcut, captures the next combo **on `window` (capture phase)**, Esc / outside click / window blur cancels, resume on stop. Stores `Ctrl+Alt+Shift+Super` + key from `event.code` (`KeyK`→`K`, `Digit1`→`1`, else the code, e.g. `Space`). Requires a modifier unless F-key. Displays ⌃⌥⇧⌘ on mac, "None" for an empty value; optional `id` for an external `<label htmlFor>`.
- `history/` — `History.tsx` (list, total, reload), `HistoryCard.tsx`, `HistoryDetails.tsx`, `format.ts`. Cards, hover copy/delete icon buttons, empty state, reloads on `history-changed`. ## Learnings / gotchas

- **WebKit doesn't focus a `<button>` on click** (Safari/WKWebView). Key handlers on the button never fire in the app while jsdom tests pass. Capture keys on `window`; reproduce in tests with `fireEvent.click` (no focus) instead of `user.click`.
- **WebKit ignores padding/height on native `<select>`** unless `appearance: none`; give inputs and selects the same explicit height and draw the chevron as a background SVG.
- **WKWebView leaves stale pixels after an opacity transition** (transparent window + vibrancy): hover-revealed history actions stayed painted on several cards while their computed opacity was 0. `.card-actions` keeps its own layer (`will-change: opacity`) and toggles `visibility` with the opacity; if artifacts persist, drop the transition.
- **user-event key syntax:** `[KeyK]` presses a physical code; `{KeyK}` is a key *name* and won't set `code`.
- **Tauri mocks teardown:** unmount cleanup calls `unlisten` asynchronously; `clearMocks()` must wait a tick (`src/test-setup.ts`) or `unregisterListener is not a function` errors appear after passing tests.
- `listitem` has no accessible name from content; use `aria-label` when querying chips by role+name.
- **Accessory (tray-only) apps aren't activated when a window is created**; the window gets made key but keyboard focus stays in the previous app (no caret). `set_focus()` after creating/showing is the fix — believed, not yet confirmed in the running app.
- **Ad-hoc signing changes the code signature every rebuild**, so macOS re-prompts Keychain access and may drop Microphone/Accessibility grants. This is why the keychain was removed (key now plaintext in SQLite, deliberately). Stable alternative if ever needed: self-signed code-signing cert. Sharing with other Macs needs notarization (paid account) or users clearing quarantine; Windows/Linux sharing was the reason for Tauri over Swift.
- **OpenAI transcription (checked Oct 2026):** `gpt-transcribe` is the recommended model; it takes `languages[]` (never send `language` too), `keywords[]`, `prompt`; response `{text, languages}`. `gpt-4o-transcribe`/`gpt-4o-mini-transcribe` and `whisper-1` (legacy) use singular `language`; `whisper-1` prompt ≤ 224 tokens. Max file 25 MB. Docs: https://developers.openai.com/api/docs/guides/speech-to-text
- **macOS shortcut conflicts:** ⌘Space Spotlight, ⌥⌘Space Finder, ⌃Space / ⌃⌥Space input sources (swallowed before the app sees them), ⌃⌘Space emoji. ⌥Space is Alfred/Raycast's default. On non-US layouts avoid ⌥+letter/digit (types characters). Default is ⌘⇧;; it shadows Cocoa's ⌘: "Show Spelling and Grammar" while yap runs. Shortcuts use physical key codes, so ; is the key right of L on any layout.
- `tauri::WebviewUrl::App("index.html?view=…")` joins correctly, but the app now opens plain `index.html`.
- Spotlight indexes `src-tauri/target/release/bundle/macos/yap.app` as a second "yap"; `touch src-tauri/target/.metadata_never_index` hides it. Two running copies fight over the global shortcut.
- App data: `~/Library/Application Support/com.mklinovsky.yap/yap.db`. A stale Keychain item (service `com.mklinovsky.yap`, account `api-key`) may remain from the keychain era.

- **A clickable floating window always activates the app on macOS.** `focusable(false)` only makes tao's `NSWindow` subclass refuse key/main; a click still activates yap, so the target app loses focus and Cmd+V would miss (confirmed in a spike, Oct 2026). Only a non-activating `NSPanel` avoids it (Whispering uses `tauri-nspanel` with `StyleMask::nonactivating_panel()`); on Windows `focusable(false)` maps to `WS_EX_NOACTIVATE`. This is why transformations are picked from the tray, not from a floating picker.
